# Qt Process Template

Шаблон desktop-приложения на **Qt 6 Widgets** под Windows, похожий по идее на Task Manager / Process Explorer.

## Что уже есть

- левый **icon-only sidebar**;
- 4 вкладки:
  - **Сведения** — работает;
  - вкладка 2 — производительность: карточки ЦП (график на каждое логическое ядро),
    памяти, GPU и звука на реальных данных, см. «Вкладка производительности» ниже;
  - **Поиск** — какие процессы держат открытый хэндл или загруженную DLL, см. «Вкладка поиска» ниже;
  - **Настройки** — шестерёнка внизу панели, состояние и управление службой мониторинга;
- список процессов, обновляемый **1 раз в секунду**;
- режимы **список / дерево**;
- кнопки:
  - **Запустить новую задачу**;
  - **Завершить задачу**;
  - **Дерево / Список**;
- хоткей **Alt+T** для переключения списка/дерева;
- двойной клик по процессу открывает пока простое окно-заглушку;
- SVG-иконки в ресурсах.

## Колонки

Сейчас реализованы:

- Имя
- ЦП
- PID
- Состояние — заглушка, всегда «Выполняется», колонка по умолчанию скрыта
- Resident RAM — весь резидентный набор (`WorkingSetSize`: приватные + разделяемые резидентные страницы)
- Committed RAM — commit charge процесса (`PrivateUsage`)
- Диск, MB/s — чтение + запись через ETW-службу
- Сеть, MB/s — отправка + приём TCP/UDP через ETW-службу
- Командная строка
- GPU D RAM / GPU S RAM — dedicated и shared видеопамять, через PDH

Колонки включаются и выключаются правым кликом по заголовку, сортировка — левым кликом.
`Командная строка` растягивается и ужимается последней.

**Имя пользователя пока не реализовано.** Сама выборка SID через токен процесса
написана (`queryUserName` в `ProcessProviderWin.cpp`), но не подключена и колонки
для неё нет — `ProcessEntry::userName` всегда пустой.

## Служба мониторинга

GUI имеет manifest `asInvoker`; установку и управление выполняет отдельный `QTaskManagerSetup.exe` с UAC. Служба работает как LocalSystem с автоматическим запуском, но ETW включается только при подключении GUI. После последнего клиента сбор останавливается через 5 секунд; тайм-аут молчащего клиента — 15 секунд.

Соберите `cmake --build build-monitoring --target monitoring-package` и запускайте GUI из `build-monitoring/monitoring-package`. При подтверждённом отсутствии службы приложение один раз предложит открыть настройки. Отмена предложения запоминается; установка всегда доступна по шестерёнке. «Отключить» останавливает службу и отключает автозапуск, «Включить» восстанавливает их. Удаление службы не удаляет PawnIO.

MB/s = 1 000 000 байт/с, интервал фактический. Диск означает физический DiskIo, а не все логические операции с файлами. ETW доставляет события с задержкой; потери и неопределённые PID/TID помечаются как неполные данные. Прочерк означает отсутствие свежего измерения. Температуры и PawnIO пока представлены интерфейсами для следующего этапа; установка драйвера в этой сборке недоступна.

Состояние проверок и команды: [test/monitoring/README.md](test/monitoring/README.md). Системная установка, реальные счётчики и расходы ETW требуют отдельной проверки; результаты unit-тестов их не заменяют.

## Вкладка поиска

Аналог Process Explorer → Find Handle or DLL. Под заголовком — строка поиска; поиск
перезапускается при вводе с задержкой 2 с (Enter запускает сразу), идущий поиск при вводе отменяется.

- Ищется подстрока без учёта регистра в именах всех открытых хэндлов системы
  (`NtQuerySystemInformation(SystemExtendedHandleInformation)` + `DuplicateHandle` + `NtQueryObject`)
  и в путях загруженных модулей (`EnumProcessModulesEx`).
  Типы хэндлов: File, Key, Section, Mutant, Event, Semaphore, Directory, Timer, Job, Desktop,
  WindowStation, SymbolicLink, ALPC Port, Session, Partition, KeyedEvent, Callback, Process.
  Пути файлов показываются как `C:\...`, ключи реестра как `HKLM\...` / `HKU\...`; совпадение ищется
  и в исходном NT-имени (`\Device\NamedPipe\...`).
- Колонки: процесс, PID, тип, дескриптор, имя (хэндла или модуля), командная строка. Сортировка по клику.
- «Завершить задачу» в шапке завершает процесс выбранной строки; двойной клик (или Enter) переходит
  к нему на вкладке «Сведения».
- Имя файлового объекта запрашивается из вспомогательного потока с таймаутом: на синхронных
  пайпах `NtQueryObject` зависает навсегда, если в другом потоке висит чтение. Зависший объект
  запоминается и пропускается; поток снимается через `CancelSynchronousIo` либо бросается.
- Без прав администратора часть процессов недоступна: их число показано в строке статуса.
- Не больше 10000 результатов.

## Вкладка производительности

ЦП, память и GPU опрашиваются раз в секунду в отдельном потоке (`PerformanceMonitor`) с
момента запуска, поэтому при открытии вкладки на графиках уже есть история.

- **ЦП**: имя — из реестра (`ProcessorNameString`); загрузка по ядрам и общая — PDH
  `\Processor Information(*)\% Processor Utility`, как у Диспетчера задач (с учётом частоты,
  а не просто занятое время; выше 100% обрезается); тёмная часть графика — `% Privileged Utility`;
  скорость — `Processor Frequency × % Processor Performance`; процессы, потоки, дескрипторы —
  `GetPerformanceInfo`; время работы — `GetTickCount64`.
- **Память**: объём и тип в заголовке — `GetPhysicallyInstalledSystemMemory` и SMBIOS
  (структуры типа 17); используется, доступно, выделено, пулы — `GetPerformanceInfo`;
  кэшировано и структура памяти — PDH-счётчики списков страниц (modified, standby, free);
  «сжатая» — рабочий набор процесса Memory Compression из `NtQuerySystemInformation`.
- **GPU**: адаптер с наибольшей выделенной памятью по DXGI; загрузка 3D и Video Decode —
  PDH `\GPU Engine(*)`, движок одного типа берётся самый загруженный, «Использование» —
  самый загруженный движок вообще; память — PDH `\GPU Adapter Memory(*)`; температура —
  `D3DKMTQueryAdapterInfo(KMTQAITYPE_ADAPTERPERFDATA)`, строка скрывается, если драйвер
  её не отдаёт. Объёмы памяти — из DXGI, поэтому у карты на 8 ГБ выделенной будет ~7,8 ГБ.
- **Звук** (опрос только пока вкладка открыта): громкость устройства вывода по умолчанию —
  `IAudioEndpointVolume`, ползунок её меняет; списки — активные устройства Core Audio, выбор
  делает устройство устройством по умолчанию для всех ролей через недокументированный
  `IPolicyConfig` (им же пользуются настройки звука Windows, EarTrumpet, SoundSwitch).

## Сборка

### CMake

```powershell
cmake -S . -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.x.x/msvc2022_64"
cmake --build build --config Release
```

Если собираешь из Qt Creator, просто открываешь `CMakeLists.txt`.

### Windows exe

在装好 MSVC、CMake 和 Qt 6（Widgets、Svg）的 Windows 上：

```powershell
./packaging/package-exe.ps1
```

脚本会编 Release，用 `windeployqt` 收齐 Qt 运行库，并打出 `packaging/output/QTaskManager-win64.zip`。解压后运行 `QTaskManager.exe`。磁盘和网络计数依赖同目录里的 `QTaskManagerService.exe`，第一次可由 `QTaskManagerSetup.exe` 安装。

## Ограничения текущего шаблона

- command line читается через PEB и требует `PROCESS_VM_READ`, которого система не даёт
  для защищённых процессов и процессов чужих пользователей — для них показывается путь к
  образу. Остальные метрики при этом не теряются: снапшот откатывается на
  `PROCESS_QUERY_LIMITED_INFORMATION` отдельным хэндлом;
- `SeDebugPrivilege` поднимается на старте, но часть процессов всё равно остаётся закрытой,
  если приложение запущено без прав администратора;
- дерево строится по `PPID` с проверкой времени создания родителя — Windows переиспользует
  PID, и без этой проверки процессы уезжают к посторонним «родителям»;
- модель обновляется инкрементально: исчезнувшие строки удаляются, оставшиеся обновляются
  на месте через `dataChanged`, новые вставляются, а пересортировка объявляется через
  `layoutChanged` с переносом persistent-индексов. Благодаря этому вид сам сохраняет
  выделение, раскрытые узлы и позицию скролла — руками это больше нигде не восстанавливается;
- когда умирает родитель, его живые дети пересоздаются в корне и теряют своё раскрытое
  состояние — это единственный случай, когда строки «моргают»;
- CPU считается по дельте `GetProcessTimes` между тиками, как в `top`: 100% — одно ядро
  загружено целиком, два крутящихся треда — 200%, потолок — 100% × число логических ядер.
  Интервал меряется отдельно для каждого процесса, вокруг его собственного `GetProcessTimes`,
  а не одним таймстемпом на тик. Для процессов, которые не открылись, CPU всегда 0.
